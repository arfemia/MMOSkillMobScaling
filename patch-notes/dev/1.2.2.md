Requires Ziggfreed Common 2.3.0 and MMO Skill Tree 1.7.1, the Update 7 builds; the three ship together. No behaviour change.

- **The 0.7 server line.** `ServerVersion` reads `>=0.7.0-pre.0 <0.8.0`. The engine matches pre-releases npm-strict, so the old `>=0.6.0-pre.13 <0.7.0` listed the jar as outdated on a 0.7.0 pre-release. New `ManifestTargetTest` reads the processed manifest with the engine's own `SemverRange` and checks that it admits the server jar the build compiles against and that line's release, and claims no later line.
- **The lockstep floors move with the pins.** `ziggfreedCommonVersion` 2.3.0 and `mmoSkillTreeVersion` 1.7.1, with the manifest floors `>=2.3.0` and `>=1.7.1`; `ManifestTargetTest` pins each floor to the jar on the test classpath, so a pin bump that forgets its floor fails the build. A 0.7.0 server with the 0.6.8-built CommonLib 2.2.0 or MMO Skill Tree 1.7.0 now refuses mob scaling by name.
- **The deprecation gate keeps its two markers.** `DamageSystems.ArmorDamageReduction` (the damage filter's ordering target, which the engine still registers) and `ISpawnProvider.getSpawnPoints()` (the distance ramp's origin) are still plain `@Deprecated` on 0.7.0 with no successor; nothing new is deprecated under this mod's calls.
