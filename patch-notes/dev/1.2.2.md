Requires Ziggfreed Common 2.3.0 and MMO Skill Tree 1.7.1, the Update 7 builds; the three ship together. The outgoing damage multiplier moves onto a native effect (after armor); the mob inspector also shows each affix's description.

- **The outgoing multiplier is a native `OutgoingDamage` effect (W2-35 card B, R232).** `outDmgMult`, with an affix's `FoldDeltas.OutDamage` (Venomous) folded in, is put on at roll as a runtime effect from Ziggfreed Common's `RuntimeEffectGrid` (`event/OutgoingDamageEffect`: one shared asset per bucket, geometric 2% steps, ids `Mmoscaling_OutDamage_All_<n>`) keyed on `Physical`, `Projectile` and `Elemental`, which the engine matches against a hit's type by its parent walk; `MobScalingEffectApplySystem` reconciles it with the affix effects. It applies after the target's armor, where the old filter multiplied before it. `inDmgMult` stays in `MobScalingDamageFilter`, since the engine's inbound lookup needs an exact type match.
- **`Armored` resists `Crush` (W2-35 card A).** `Mmoscaling_Affix_Armored` adds Update 7's `Crush` beside `Physical`, `Bludgeoning`, `Slashing` and `Projectile`. The `Ward_*` effects already key native types, so with MMO Skill Tree's per-ability types and Seasons of Orbis's `Hallows_Eve_Lantern_Burst` retired, a ward now covers every hit of its type.

- **The 0.7 server line.** `ServerVersion` reads `>=0.7.0-pre.0 <0.8.0`. The engine matches pre-releases npm-strict, so the old `>=0.6.0-pre.13 <0.7.0` listed the jar as outdated on a 0.7.0 pre-release. New `ManifestTargetTest` reads the processed manifest with the engine's own `SemverRange` and checks that it admits the server jar the build compiles against and that line's release, and claims no later line.
- **The lockstep floors move with the pins.** `ziggfreedCommonVersion` 2.3.0 and `mmoSkillTreeVersion` 1.7.1, with the manifest floors `>=2.3.0` and `>=1.7.1`; `ManifestTargetTest` pins each floor to the jar on the test classpath, so a pin bump that forgets its floor fails the build. A 0.7.0 server with the 0.6.8-built CommonLib 2.2.0 or MMO Skill Tree 1.7.0 now refuses mob scaling by name.
- **New: a `casters/` owner layer.** `config/CasterOwnerLayer` scans `mods/MmoMobScaling/casters/<id>.json` through `OwnerFiles` (the `difficulty/` folder's convention: the stem is the id, a `Payload` wrapper is peeled, a `README.txt` is seeded at setup) into `CasterRosterConfig`'s owner layer. A file overlays the same-id shipped roster per leaf (`CasterRosterAsset.overlayOn`: an authored `Enabled`, `Role` or `Abilities` wins whole, an absent one inherits), so `{"Enabled": true}` alone switches `Demo_Boss_Caster` on; a file for an id nothing ships must carry its own `Role` or it is skipped with a warning. `CasterRosterConfig` now keys every layer by `OwnerFiles.idKey`, as `DifficultyConfig` does, and keeps the pack layer for the overlay (`packRoster`). The caster store's load refolds the owner layer after the pack fold, then rebuilds `Rosters` and validates the folded set, owner files included.
- **The caster boot line counts on and off apart**: `Mob-scaling caster rosters loaded: <on> on, <off> off (<n> from mods/MmoMobScaling/casters).` The old `<n> entries (pack layer)` counted the shipped demo, which is off.
- **`hud.zone.location` is gone** from all nine locales; nothing read it.
- **The deprecation gate keeps its two markers.** `DamageSystems.ArmorDamageReduction` (the damage filter's ordering target, which the engine still registers) and `ISpawnProvider.getSpawnPoints()` (the distance ramp's origin) are still plain `@Deprecated` on 0.7.0 with no successor; nothing new is deprecated under this mod's calls.
- **The mob inspector paints each affix's description.** `MobInspectorHud` sets `#Affix<n> #Desc.TextSpans` from `MobScalingTextUtil.affixDescKey` (the affix's `DescriptionKey`, else `mmomobscaling.affix.<id>.desc`), the keys every shipped affix already carries in all nine locales, so no lang key is added. `ContentKeys.known` decides the line: a key no loaded language carries (a pack affix that authors none) hides it rather than paint the raw key. The name and the description both go out through `ContentKeys.tr`, so a bare authored key reaches the client as its registered id; a name key nothing ships keeps `ContentKeys`' traceable raw-key fallback, so a chip is never an unnamed icon. In `Hud/MmoscalingMobInspector.ui` the chips sit under a 72 high `#MmoscalingInspectHeader` (the portrait beside the name, tags and HP bar) and stack one per line across the full 292 inner width: the `@AffixChip` template is the icon and name line (18) over `#Desc` (`@InspectAffixDescStyle`, the 13 caption step with `Wrap: true, WrapMaxLines: 2`, top-aligned, at a fixed `Width: 292, Height: 32`), so the longest translation (73 characters) shows whole. The fixed width is what makes two lines safe: a wrap-2 label crashes the client only once its width drops under one ellipsis, and `#Desc` is never FlexWeight. The card's height follows its chips: `panelHeightFor(chips, descLines)` (92 bare, then 6 above the chips, 18 a chip, 32 a description, 4 between chips, so 148, 202, 256 and 310 for one to four described chips) backs `panelHeight()`, and a push that changes it re-sends the anchor at the configured corner, so a bottom corner grows upward. The skip-cache signature is unchanged, since both text keys follow the affix id.
