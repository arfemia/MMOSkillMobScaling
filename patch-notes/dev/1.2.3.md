Requires Ziggfreed Common 2.3.0 and MMO Skill Tree 1.7.1, as 1.2.2 did: nothing here calls newer API, so both manifest floors stay and this release ships on its own. Two shipped world rules hold the Headless Horseman's graveyard in a band, the tier auras stop trailing, the per-world caches drop a removed world and the inspector never reads 0 on a living mob; dead code, two dead tests and an orphaned demo role go.

- **The Headless Horseman's graveyard sits in a band.** Two shipped world rules, `Worlds/Hallows_Eve_Graveyard.json` (copies named `hallows_eve_graveyard-<n>`: `Floor` and `MinCap` 1, `MaxCap` 10) and `Worlds/Hallows_Eve_Graveyard_Hard.json` (`hallows_eve_graveyard_hard-<n>`: 15, 15, 25), each with `DistanceEscalation` off and `PlayerScalingStartRingBlocks` 0, so a group's power counts inside a dungeon copy and raises the level only to the cap. A dungeon copy is a void instance with no zone, so the global world floor applied there before. Elite rolls stay on. An owner file of the same name in `mods/MmoMobScaling/worlds/` replaces either. No test (smoke).
- **A rare mob's aura no longer leaves a trail.** The five aura effects (`Mmoscaling_Aura_Rare`, `_Epic`, `_Legendary`, `_Boss` and `_Horrific`) author `OverlapBehavior` `Ignore` where they wrote `Extend`. A chunk-reloaded mob is rolled again a tick after its viewers have it, and the outgoing-damage bucket's landing re-runs the whole reconcile (`retryWhenLanded`), so the aura was applied again; the engine sends an Add on every infinite apply, and the client met each with another set of the aura's drop particles while the old set kept running. With `Ignore` the client keeps the set it shows. On the server an infinite effect never reads its `OverlapBehavior` (`EffectControllerComponent.addEffect` sends it to `addInfiniteEffect` first), so nothing else changes; the re-roll and the reconcile are unchanged. The fix itself is Ziggfreed Common 2.4.0's: its `EffectAdds` never sends the repeat Add at all, and `Ignore` is the client-side backstop, the only part a server still on Ziggfreed Common 2.3.0 gets. No test (smoke).
- **The per-world caches drop a removed world.** Three evictors on Ziggfreed Common's `WorldEvictors.registerEvictor`, registered inside the enabled branch and fanned out by the library's own `RemoveWorldEvent` listener: `ZoneDifficultyResolver.onWorldRemoved` (the per-world memo of seed, spawn point and chunk zone names; the method existed but nothing called it), the new `MobScalingConfig.onWorldRemoved` (`worldViewCache` and `nameOnlyViewCache`) and the new `RegionPowerTracker.onWorldRemoved` (the world's presences, buckets and declared fold). Every instance world (`instance-<name>-<uuid>`) left all three behind, and a world reusing a removed world's name read the old memo's seed and spawn point. The engine dispatches `RemoveWorldEvent` before the world stops ticking, so a last tick in that window can still leave an empty bucket map and a fold for the dying world (well under a kilobyte, not the growth this fixes).
- **The preset argument has its description.** `command.arg.preset_name`, named by `MobScalingCommand` since 0.5.0, was in no lang file, so the `/mobscaling` help showed the raw key. It lands in all nine locales.
- **The 1.1.0 demo role is gone.** `Server/NPC/Roles/MmoMobScaling/Mmoscaling_Caster_Demo.json` and `Server/NPC/Balancing/MmoMobScaling/CAE_Mmoscaling_Caster_Demo.json` referenced only each other. `Mmoscaling_Demo_Dodge`, the `Demo_Boss_Caster` roster's native chain, stays.
- **Dead code removed.** The five `MobScalingConfig.set*Runtime` HUD setters (no caller: `/mobscaling hud` persists through `MobScalingOwnerWriter` and refolds), eight `MobScalingOwnerWriter` wrappers and their leaf constants (`saveRaritySpawnChance`, `saveDifficultyMinCap`, `saveDifficultyMaxCap`, `saveEscalationStart`, `saveEscalationBlocksPerPoint`, `saveEscalationMaxBonus`, `saveEscalationRarityPerPoint`, `saveInspectorRange`; the admin page writes those leaves through `saveLeaves`) and `RegionPowerTracker.describePresence`, and two lines nothing read, `command.preset.usage` and `command.hud.persist_hint`, leave all nine locales. `MobScalingCommand`'s javadoc no longer calls the `hud` and `preset` changes runtime only.
- **`ScalingLangTest` checks each translated key.** Its coverage test (missing and extra keys, which the MMO's `LangKeyParityTest` covers across the family under `-PlangGate`) and `hudKeysArePresent` (it pinned the dead `command.hud.persist_hint`) are gone. The new `everyTranslatedKeyKeepsItsPlaceholdersAndHasAValue` checks, for each key a locale file carries, en-US's placeholders, a non-empty value and no em-dash, so a key new in en-US no longer fails this build before the lang wave. `MobScalingOwnerWriterTest.saveRaritySpawnChancePersistsRefoldsAndKeepsComment` went with its wrapper.
- **The inspector never shows 0 on a living mob.** `MobInspectorHud` shows current health rounded up (`hpReadout`, `Math.ceil`, floored at 0) where it rounded to nearest, so a mob left on a fraction of a point reads 1, and its skip-cache key uses the same number, so the panel repaints exactly when the shown value changes. Ziggfreed Common 2.4.0's `HealthUtil` also lands a scaled maximum on a whole point, so the fraction no longer arises from the scale itself, and fills a raised maximum with an Add (`HealthUtil.fillToMax`) that every viewer receives, so a scaled mob's bar no longer empties while it lives and its model no longer freezes; nothing here changes for that, which needs Ziggfreed Common 2.4.0.
- **A comment catches up with Update 7.** `ZoneDifficultyResolver`'s `DEPRECATION-KEPT` note on `ISpawnProvider.getSpawnPoints()` now reads the async `getSpawnPointAsync(World, UUID)` as the live sibling, not the engine's next version; the marker stands.
