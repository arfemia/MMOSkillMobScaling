Requires Ziggfreed Common 2.3.0 and MMO Skill Tree 1.7.1, as 1.2.2 did: nothing here calls newer API, so both manifest floors stay and this release ships on its own. The per-world caches drop a removed world; dead code, two dead tests and an orphaned demo role go.

- **The per-world caches drop a removed world.** Three evictors on Ziggfreed Common's `WorldEvictors.registerEvictor`, registered inside the enabled branch and fanned out by the library's own `RemoveWorldEvent` listener: `ZoneDifficultyResolver.onWorldRemoved` (the per-world memo of seed, spawn point and chunk zone names; the method existed but nothing called it), the new `MobScalingConfig.onWorldRemoved` (`worldViewCache` and `nameOnlyViewCache`) and the new `RegionPowerTracker.onWorldRemoved` (the world's presences, buckets and declared fold). Every instance world (`instance-<name>-<uuid>`) left all three behind, and a world reusing a removed world's name read the old memo's seed and spawn point. The engine dispatches `RemoveWorldEvent` before the world stops ticking, so a last tick in that window can still leave an empty bucket map and a fold for the dying world (well under a kilobyte, not the growth this fixes).
- **The preset argument has its description.** `command.arg.preset_name`, named by `MobScalingCommand` since 0.5.0, was in no lang file, so the `/mobscaling` help showed the raw key. It lands in en-US; the other eight locales follow in the release's lang wave.
- **The 1.1.0 demo role is gone.** `Server/NPC/Roles/MmoMobScaling/Mmoscaling_Caster_Demo.json` and `Server/NPC/Balancing/MmoMobScaling/CAE_Mmoscaling_Caster_Demo.json` referenced only each other. `Mmoscaling_Demo_Dodge`, the `Demo_Boss_Caster` roster's native chain, stays.
- **Dead code removed.** The five `MobScalingConfig.set*Runtime` HUD setters (no caller: `/mobscaling hud` persists through `MobScalingOwnerWriter` and refolds), eight `MobScalingOwnerWriter` wrappers and their leaf constants (`saveRaritySpawnChance`, `saveDifficultyMinCap`, `saveDifficultyMaxCap`, `saveEscalationStart`, `saveEscalationBlocksPerPoint`, `saveEscalationMaxBonus`, `saveEscalationRarityPerPoint`, `saveInspectorRange`; the admin page writes those leaves through `saveLeaves`) and `RegionPowerTracker.describePresence`. `MobScalingCommand`'s javadoc no longer calls the `hud` and `preset` changes runtime only.
- **`ScalingLangTest` checks each translated key.** Its coverage test (missing and extra keys, which the MMO's `LangKeyParityTest` covers across the family under `-PlangGate`) and `hudKeysArePresent` (it pinned the dead `command.hud.persist_hint`) are gone. The new `everyTranslatedKeyKeepsItsPlaceholdersAndHasAValue` checks, for each key a locale file carries, en-US's placeholders, a non-empty value and no em-dash, so a key new in en-US no longer fails this build before the lang wave. `MobScalingOwnerWriterTest.saveRaritySpawnChancePersistsRefoldsAndKeepsComment` went with its wrapper.
- **The inspector never shows 0 on a living mob.** `MobInspectorHud` shows current health rounded up (`hpReadout`, `Math.ceil`, floored at 0) where it rounded to nearest, so a mob left on a fraction of a point reads 1, and its skip-cache key uses the same number, so the panel repaints exactly when the shown value changes. Ziggfreed Common 2.4.0's `HealthUtil` also lands a scaled maximum on a whole point, so the fraction no longer arises from the scale itself.
- **A comment catches up with Update 7.** `ZoneDifficultyResolver`'s `DEPRECATION-KEPT` note on `ISpawnProvider.getSpawnPoints()` now reads the async `getSpawnPointAsync(World, UUID)` as the live sibling, not the engine's next version; the marker stands.
